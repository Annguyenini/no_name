# Authentication API

All endpoints use `/auth`. Body DTOs are transformed and reject unknown fields. Password sign-in and refresh failures intentionally return generic credential errors.

## Endpoint contracts

| Endpoint                               | Expected input                                                                                                                                                                       | Success output                                                                  | Common status codes and what they mean                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/sign-up`                   | `{"email":"person@example.com","password":"Example123!"}`. Email must be valid. Password: 8+ chars with lowercase, uppercase, number, and symbol.                                    | `201` `{"id":"user-uuid"}`                                                      | `400` Supabase rejected signup, commonly because the email is already registered. `401` Supabase returned no user after signup. `400` can also mean invalid DTO input.                              |
| `POST /auth/sign-in`                   | `{"identifier":"person@example.com","password":"Example123!"}`. Identifier is currently string-validated and passed as Supabase email. Password uses the strong-password rule above. | `201` `{"id":"user-uuid","access_token":"...","refresh_token":"..."}`           | `400` request body failed validation (including a weak password or extra field). `401` credentials were rejected or Supabase returned no auth data; typically the identifier/password do not match. |
| `GET /auth/sign-in-via-token`          | `Authorization: Bearer <access_token>`                                                                                                                                               | `200` `{"user_id":"user-uuid"}`                                                 | `401` access token is missing, invalid, or expired.                                                                                                                                                 |
| `GET /auth/refresh-token`              | `Authorization: Bearer <refresh_token>`; no body                                                                                                                                     | `200` `{"id":"user_id","access_token":"new-access-token","refresh_token":"new-refresh-token"}` | `401` bearer value is missing/malformed or refresh token is invalid/expired. Store both rotated tokens after success.                                                                               |
| `POST /auth/signout`                   | `Authorization: Bearer <access_token>`; no body                                                                                                                                      | `201` `{"message":"Signed out successfully"}`                                   | `401` access token invalid, or Supabase rejected sign-out with 401/403. `500` another sign-out provider failure or unexpected server error.                                                         |
| `POST /auth/resend-email-verification` | `{"email":"person@example.com"}`; valid email required                                                                                                                               | `201` empty response                                                            | `400` email DTO is invalid. `500` Supabase resend failed or returned no data.                                                                                                                       |

## Interpreting errors

- `400` usually means the request body failed validation or a provider-specific request was rejected. Read the response `message` for the route-specific reason.
- `401` means authentication or credentials were rejected. For sign-in, treat it as a generic “credentials did not match” result; the endpoint does not distinguish an unknown account from a wrong password.
- `500` means a provider or unexpected server failure. The global exception handler hides unexpected internal details and returns `{"statusCode":500,"message":"Internal Server Error","timeStamp":"..."}`.

Validation errors use HTTP `400`; `AppException` errors use `{"statusCode":<status>,"message":"...","timeStamp":"..."}`. Standard Nest HTTP exceptions retain Nest's response shape.
